# Android performance measurements

The `benchmark` app variant is release-like, non-debuggable, and isolated under the application ID suffix `.benchmark`. A local HTTPS MockWebServer runs in the Macrobenchmark instrumentation process before measurement; the isolated fixture activity loads the production Home, Logs, and Analytics Compose screens with synthetic data. The ephemeral server key stays in the instrumentation process; the app receives only its public certificate and a validated loopback URL. The synthetic API key and trust code exist only in the benchmark variant. Benchmark results measure local UI and rendering work, not NextDNS service latency.

CI builds the app and Macrobenchmark APK. The synthetic HTTPS API runs in the instrumentation process before each measured journey; only its loopback address and public certificate reach the isolated benchmark app. On a physical Android 14+ device, build with `./gradlew :app:assembleBenchmark :macrobenchmark:assembleBenchmark` and run with `./gradlew :macrobenchmark:connectedCheck`. Each journey uses two warmups followed by ten measured cold launches. The journeys cover authenticated synthetic Home startup and scrolling, a 200-row two-page log history, the analytics time series, and the interactive country map. Guest startup is a different state and is not used as this journey's baseline.

For a main-versus-candidate comparison, apply the same benchmark harness commit to each application revision and keep the device, Android build, refresh rate, locale, theme, benchmark command, and power/thermal conditions fixed. Save the application commit and benchmark commit separately with the raw Macrobenchmark JSON and Perfetto trace outputs. Report TTID and frame CPU/overrun percentiles from the run, and inspect the traces for main-thread disk/network work and Compose recomposition. A recomposition count alone is not a performance result. Keep the approved 10% regression and 5% jank review targets in the analysis; explain any miss and remeasure after a fix.

No physical-device baseline or candidate comparison has been recorded yet. The Macrobenchmark workflow is build-verified only until a physical device run completes. Emulator results must be labeled as emulator-only and cannot close the physical-device gate. The connected device run also does not substitute for BrowserStack B01–B22 acceptance.

Android's official [Macrobenchmark guide](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview) describes the separate test module, UI journeys, JSON output, and trace artifacts. `MacrobenchmarkScope.startActivityAndWait(Intent)` launches by shell command and requires the launcher category on Android 13 and later; both fixture launch paths include that category ([API reference](https://developer.android.com/reference/androidx/benchmark/macro/MacrobenchmarkScope)).
